# HIWIN 本地邮件工具

首版核心使用 Python 标准库，不需要 Make 或额外订阅。界面只绑定本机 `127.0.0.1`。若本机已安装 `certifi`，工具会使用它补充可信 CA 证书，解决部分 macOS Python 没有默认根证书的问题；TLS 证书和主机名验证始终开启。

## 启动

在此目录执行 `python3 app.py`，打开 <http://127.0.0.1:8765> 或 <http://localhost:8765>。停止时在终端按 Ctrl+C。

## 联系目的与记录工作台

每次联系先选择「ITF 2026 展位邀约」「首次合作介绍」或「负责人跟进」，再选择快捷名单和国家。模板下拉只显示当前目的的模板，保留国家及语言区分；测试国家额外显示独立的「测试邮箱专用」分组。未标注目的的旧合作模板归在「首次合作介绍」下，不影响历史邮件的活动状态。模板按联系目的及国家推荐；国家切换保留当前目的，未保存的正文不会被自动覆盖。切换目的时若保留其他目的的草稿，下拉会显示「草稿已保留 · 请选择本轮模板」，不会让选项与正文不一致。不同目的的模板另存，避免覆盖原模板。新预览将活动、模板名称、语言、实际正文和附件一起冻结；编辑及切换仍需重新预览批准。

名单分别显示同一邮箱的历史发送封数和本轮状态。「全选本轮未发」只勾选当前筛选中有有效邮箱、在该活动下没有已发送／待发送／结果待核对且没有停止标记的联系人；历史发过其他活动的邮箱仍可参与新的 ITF 邀约。点「历史」核对同公司其他邮箱，发送确认再次列出历史及本轮提醒。更换负责人邮箱时，使用独立联系人编号并关联原公司，保留原邮箱记录。

记录按一封邮件展示，统计分别标注已关联的外部公司、邮箱数及邮件封数；内部、测试和公司归属待确认的邮箱单独显示，保留原邮件类型。支持活动、快捷名单、回复／异常／待同步筛选，以及原有搜索、发件员工、国家、测试类型和分页。「查看邮件详情」显示实际发送内容及附件，发送结果与回复状态分别显示。历史邮件的活动保持「历史发送（活动未标记）」，不会根据主题猜测本轮 ITF 已发送。已删除的列表记录仍计入发送历史，避免重复发送依据丢失。

新匹配到的来信保存发件人、主题、来信日期、正文及关联依据；旧记录未保存的来信正文明确提示缺失，需要在邮箱核对。停止标记区分人工回复后转人工跟进、地址失效、手动停止和历史原因未知，手动停止不再改写原邮件的发送结果。确定地址失效只约束原邮箱；人工及未知原因的停止标记仍保守保留。

公司关联、邮箱角色、联系人及电话由本机私有 `contact_metadata.json` 补充；邮箱角色及联系人信息与其地址绑定，更换地址不会继承旧邮箱的负责人身份。当前额外字段为 2026-10-13 主表快照，已有 Sheet Bridge 仍读取原联系人字段；以后修改这些额外字段需要更新本机快照，当前不会自动同步角色或电话。备份同时保留此文件及 `contact_groups.json`。活动与回复证据保存在本地数据库，现有云端日志列继续同步，无须重新部署 Apps Script。

现有名单含 197 家机构，其中 16 家有邮箱，另有 1 个 Gmail 测试收件人。默认不选择收件人；首次使用 `contacts.json` 中的名单快照，点击「从 Google Sheet 刷新名单」后改用本地数据库保存的云端名单。页面支持按国家筛选和新增机构，新增名单保存在本地数据库。正式机构可重复发送；点击发送后会二次确认发件人、收件人、已有发送记录与停止联系标记，确认即可发送。标记为「测试」的邮箱可新建批次再次发送，每次仍需人工批准。

## 从 Google Sheet 刷新名单

2026-10-05 已将「台湾日本业务旅行社_四栏全台名单_2026-10-02.xlsx」的第一个分页「日本业务已查证」并入现有「邮件跟踪」主表：新增 299 家（TW-001 至 TW-299），其中 297 家有邮箱、2 家缺邮箱。主表现有 496 家正式机构。「台湾邮件跟踪」是同一主表的筛选视图，按国家等于台湾显示，沿用现有 Sheet 连接和 Apps Script 部署。电话保存在新增「电话」列，来源链接保存在「邮箱来源」，原电话／需求／报价／ITF 初始状态保存在备注。

发送状态、首末发送时间、实际发件人、主题、邮件 Message-ID（沿用原「Gmail邮件ID」列）、跟进次数、回复状态、回复检测时间和下一步已改为按机构编号从「轻量工具日志」自动计算。发送后或点击记录区右上角「检查回复与退信」成功同步日志时，主表和台湾视图同步更新。回复时间是检测记录时间；服务器已接受不代表最终投递。同步失败时，先在工具点击记录区出现的「重试 Sheet 同步」。自动计算列请勿手动覆盖；人工拒绝／停止联系在「勿再联系」选择「是」，并刷新联系人。初始「未核对」表示没有检测记录。台湾名单导入后需点击「从 Google Sheet 刷新名单」加载，国家筛选选择台湾；后续仍在同一主表维护姓名、邮箱、电话和备注。

在 Google Sheet 的「邮件跟踪」页修改机构名称、国家或收件邮箱后，点击联系人区「从 Google Sheet 刷新名单」。工具通过现有 Apps Script 的签名连接读取最新名单，按机构编号替换云端联系人快照；同一机构请保持编号不变，新增机构需填写独立编号。界面显示刷新时间与新增／更新／移除数量。不会后台轮询，记录区「刷新」只读取本地记录。

云端删除的联系人会从云端名单移除，本地新增联系人与测试邮箱仍保留。发送历史、模板和员工设置不受覆盖；本地停止联系标记保留，同一机构更换邮箱后，人工或未知原因的停止标记继续保留，已确认旧地址失效的标记不会转移到替代邮箱。表格可选「勿再联系」列中的是／yes／true／1，或「发送状态」中的勿再联系／停止联系／已停止，会为该联系人显示停止提醒，仍可勾选并在二次确认后手动发送。邮箱格式无效的机构仍显示，但不能勾选，需回表格填写单一完整邮箱。

刷新后须重新预览批准。断网、错误来源、空名单或重复编号时保留原名单，并提示修正。首次升级到此功能，需要在现有 Apps Script 项目保存新版 `SheetBridge.gs`，通过「管理部署 → 编辑 → 新版本 → 部署」更新原部署；原 URL、签名密钥和发送结果同步继续使用。新部署需按下方步骤配置脚本属性并验证。

2026-10-13 已将参展商第一页的 54 个单位并入现有主表，复用 6 条、增加 48 条收件记录；主表共 544 条收件记录，同公司的其他邮箱不重复计作新公司。三组为旅行社 28 个、旅行相关 15 个、航空交通 11 个，合计 49 个有效邮箱、5 个缺邮箱。J3302 中英文展位邀约模板已在当前本机数据库单独保存，附对应语言的住宿宣传册；原有模板正文和发送历史保留。

ITF 参展商联系人并入同一「邮件跟踪」后，在「快捷名单」分别选择「ITF 旅行社」「ITF 旅行相关」或「ITF 航空公司」。三组独立筛选，不显示合并的 ITF 名单。「ITF 航空公司」沿用来源表的航空交通运输分类，包含邮轮与港口联系人。

选择或切换 ITF 分组后清空勾选与搜索，国家切到「全部国家／地区」；随后可用国家、搜索和「仅显示有邮箱」进一步筛选。调整国家时保留当前 ITF 分组。ITF 名单可以包含多个国家，同一公司新增负责人邮箱时使用独立收件记录编号，既有联系人与发送历史保留。界面显示实际加载的联系人数量；缺邮箱联系人仍可查看，全选只勾选有效邮箱。

没有该文件时只显示内置台北名单；格式错误时保留内置名单并明确显示配置加载错误。修正文件后刷新工具网页即可，无需重新部署 Apps Script。快捷名单只控制收件人筛选，选完后仍需核对邮件模板并重新预览批准。

## 删除收件联系人与批量新增

收件人每行右侧可点「删除」，也可勾选后在「名单维护」里点「删除已选联系人」，确认后从本地工具移除该机构及邮箱。删除标记跨刷新与重启保留，表格导入的联系人也不会被再次刷新恢复。Google Sheet 原名单、发送与回复历史、停止联系标记均保留。涉及的未发送预览与批准失效；有定时任务须先取消，正在发送的批次须等待结束。

联系人维持单向读取：在 Google Sheet「邮件跟踪」批量新增多行，填写独立「机构编号」、机构名称、国家、收件邮箱，点击「从 Google Sheet 刷新名单」即可加载；刷新网页或「刷新」不读取表格名单。工具内新增／删除联系人不写回表格。发送与回复日志仍按原流程同步到表格。

## 公司邮箱连接

在本地页面输入公司邮箱密码，点击连接。默认示例 `employee@hiwin-japan.co.jp`，可通过本机配置或界面改为自己的员工账号，SMTP `mail1039.onamae.ne.jp:465`，IMAP 同主机 `:993`，使用 SSL/TLS 和证书验证。公司 SMTP 发信已由用户完成真实测试；IMAP 回复检查仍需实际来信验证。若账号禁止 SMTP/IMAP，需要邮箱服务商或管理员开通。

密码仅在当前 Python 进程内存中，不写数据库，不交给 Make。网页登录状态不能替代 SMTP 登录。重启后重新输入。

## 国家、模板、附件与链接

收件人按国家分组，可筛选或搜索，也可勾选「仅显示有邮箱」。点击「全选（含已发过的）」会替换原来的勾选，只选择当前国家和搜索筛选下有有效邮箱的联系人，跳过缺邮箱或无效邮箱的机构，选择数量不限。预览与发送均无每批或每日数量上限。已选数量同时显示机构数和去重邮箱数，切换筛选不会清空选择，并提示隐藏的选择。已选区域同时列出全部已选机构的名称、邮箱与国家，包括当前筛选外的联系人；可逐项「取消选择」，长名单在区域内滚动查看。发送与回复记录可独立按国家筛选，历史记录会补上国家。

初始模板有 English 测试、通用 English 合作洽询、繁體中文（台灣）及 English 台灣 ITF 合作邀約。分别编辑主题、正文、链接与附件，点击底部固定栏的「保存模板」，或修改名称后「另存为新模板」。数据跨重启保留。模板选择框按文件夹收起：默认按国家归类（美国、加拿大归入「北美」，德国、丹麦等归入「欧洲」），也可在「模板名称、文件夹与语言」里填写文件夹；填「已归档」的模板排在最后，不会被自动推荐。可在选择框里搜索模板名称、国家或语言。变量支持 `{{agency_name}}`、`{{test_id}}`、`{{sender_name}}`、`{{sender_email}}`。切换模板暂存未保存的编辑；关闭页面前请保存。

网页链接每行写 `名称 | https://...` 或网址，支持 HTTP/HTTPS；也可直接在正文输入网址。写了名称的链接在 HTML 邮件里只显示名称，点击打开网址，适合带 UTM 追踪参数的长链接。正文可点「🔗 插入链接」（⌘K / Ctrl+K）：先选中文字再点，只需输入网址；不选文字则先输入显示文字。正文中保存为 `[显示文字](https://...)`。纯文字版本仍写出完整网址，如 `显示文字 (https://...)`。邮件有纯文字和 HTML 两种版本，HTML 中网址可点击。附件支持多文件，原始大小合计上限 10 MB；存放在本机 `uploads/`，与保存的模板关联。邮件编码后的实际大小会增加，服务商可能另有限制。

批准绑定当时的名单、实际主题和正文、链接及附件文件内容；改动后需要重新预览批准。发送前校验附件内容，文件被改变时拒绝发送。备份时一起保留 `outbox.sqlite3`、`uploads/`、`assets/`；Sheet 连接在 Mac 钥匙串中单独保存。

## 员工邮箱切换与测试标记

在「连接 → 新增员工邮箱」填写 `@hiwin-japan.co.jp` 或 `@andclan.co.jp` 完整地址和员工名称，点击「保存并切换员工」，输入该员工自己的邮箱密码连接。目前这两个域名已确认使用 Onamae 1039 网页邮箱，沿用已配置的服务器；其他域名需先核对服务器。新增员工未保存时禁止输入密码或连接，避免用旧账号验证新密码。535 错误会显示实际登录账号与服务器。所有已配置账号共用 SMTP `mail1039.onamae.ne.jp:465` 和 IMAP `:993`。账号列表与上次选择保存在本地数据库，密码仍只在当前进程中；各员工通过验证后的密码在本次进程中按账号分别保留；切回已验证员工无需重复输入。连接失败只清除该员工的连接，重启后所有员工都需重新连接。密码不写文件或钥匙串。切换账号仍会使未执行的预览／批准失效，切回也不能沿用旧批次。该工具当前只有一个活动发件账号，不是多个员工同时操作的独立会话服务。

使用 `{{sender_name}}` 和 `{{sender_email}}` 自动替换员工名称和当前发件邮箱。初始模板会采用姓名变量；已由用户改过的模板保持原文，若有写死的署名，请改成变量或在批准前核对署名。发送记录保存实际发件人，记录区可同时按测试／正式、发件员工和国家筛选；检查回复只读取当前员工邮箱的收信文件夹，并按实际发件账号关联记录。发送历史与停止联系提醒跨员工共用，换账号后仍会显示已有发送记录，二次确认后可继续发送；测试邮箱允许重新预览批准后再发送。

测试模板、测试国家筛选、测试收件人、预览、发送按钮及记录采用橙色与 `TEST／测试` 文字区分。测试邮箱不受停止联系与跨批次重复发送限制，但同一批次不可重复执行和发送前批准仍然适用。如果同一地址也登记为正式机构，则按正式机构处理。测试和正式收件人不能放进同一批；测试模板不能发给正式旅行社。正式合作模板仍可以发给测试邮箱，便于检查真实内容。

发给测试邮箱的主题自动追加日期时间与本批编号，便于把连续测试分开查看；预览、批准、发送和记录使用同一个主题。正式收件人的主题不加测试编号。Gmail 仍可能折叠它识别出的签名或重复内容，发件工具不能强制收件端显示。

新版 `SheetBridge.gs` 在既有 13 列后追加实际发件员工、国家和附件名称，并为测试记录加橙色底。更新既有部署时保留 URL 与签名密钥，并设置 SPREADSHEET_ID 脚本属性。

## 员工联系署名

展开「自定义联系方式与二维码」，可编辑当前 sender 的署名姓名、联系邮箱、LINE 链接与二维码，以及 WhatsApp 电话、链接与二维码。留空的姓名／联系邮箱采用员工名称／发件邮箱；SMTP 发件账号仍由上方选择控制。二维码支持上传裁剪好的 PNG／JPG（最多 2 MB），也可移除。默认两个 sender 共用 WhatsApp；取消「使用共用 WhatsApp」后可分别保存各自设置。修改共用设置会同步作用于所有使用共用设置的账号。配置保存在本地数据库，重启保留；保存后旧预览与批准失效，需重新预览确认。

英文模板（含英文测试与副本）会显示裁剪后的共用 WhatsApp 二维码，预览与 HTML 邮件都以 180 × 180 像素显示，通过 MIME 内嵌图片发送。二维码和真实联系配置不包含在公开仓库；首次使用请在界面配置。可配置的联系方式使用 `{{sender_contact_email}}`、`{{sender_whatsapp_phone}}`、`{{sender_whatsapp}}`、`{{sender_line}}` 变量。

台湾版与英文版称呼使用 16px 正常字重，正文使用 14px；公司名称采用「株式会社 HIWIN」／「HIWIN Co., Ltd.」，主题、正文与署名一致。正文中的完整公司名称与 Apartment Hotel 11 自动加粗，网址和邮箱地址保持完整。英文版保留英文段落与空行，姓名、联系方式的加粗和分隔线保留。预览与实际 HTML 邮件共用文字分段。

HTML 邮件通过明确的 `<br>` 标签保留正文换行和段落空行，不依赖邮箱客户端对 `white-space` 样式的支持。更新程序后需重启工具并重新生成预览；已冻结的批次与已发出的邮件不改变。

台湾版使用 `{{sender_line}}`，随发件员工切换 LINE 链接。员工的可选初始映射保存在本机 `sender_contacts.json`，图片在 `assets/`，可在界面更新。邮件在署名下方以 180 × 180 像素显示二维码，通过 MIME 内嵌图片发送；纯文字版本保留 LINE 链接。预览会显示同一张二维码，批准绑定图片的内容摘要，图片改变后必须重新预览批准。只在台湾版及使用台湾语言设置的副本中加入二维码；新员工未配置 LINE 时不会误用其他员工联系方式。英文版两位员工默认共用 WhatsApp 电话与二维码，电话、联系链接和图片可在界面配置；LINE 仍可按员工分别设置。

## 首封测试

1. 选择 English 测试模板，在「测试」国家中勾选 `你配置的测试邮箱`（测试邮箱可反复测试，每次新建并批准批次）。
2. 点击底部固定栏的「生成预览」，检查实际机构名、收件人、主题和正文。
3. 勾选确认并「批准本批」。直到点击「发送已批准批次」才发送。
4. SMTP 成功后记录「服务器已接受」。在 Gmail 收件箱和垃圾箱检查实际收件；服务器接受不代表投递或进入收件箱。

批准绑定冻结内容和完整名单。修改内容需生成新批次。预览、立即发送与定时发送均无每批或每日数量上限，邮件间隔 8 秒。只批准不发送。程序重启或网络错误产生「结果待核对」时不能自动重发。正式邮箱已有成功、待核对或停止记录时，二次确认窗口显示相关提醒，确认后可发送。确认绑定该批次与最新发送／回复记录；记录变化时重新点击发送确认。已执行批次需新建预览批准，以免双击重复执行。

SMTP 发信未自动保存到公司邮箱的「已发送」文件夹；本地数据库保存实际正文和 Message-ID。结果不明确时需通过收件人／邮箱服务商核对，不能只凭已发送文件夹空白认定没有投递。

发送时显示「发送中 x/x」与进度条，每秒更新当前批次已处理笔数、服务器已接受、失败、结果待核对及未发送数量。异常暂停不会显示为全部成功；完成后保留本批结果和 Sheet 待同步数量。重新打开页面也会显示最近批次的进度，定时执行中的任务会自动更新。

## 按国家保存模板与网站

切换「收件人国家／地区」时，优先加载该国家上次保存的模板；没有已保存模板时，台湾使用原繁体模板，其他国家使用英文合作模板，测试国家使用测试模板。在「模板设置」里选择「绑定国家／地区」并保存，首次会创建该国家的独立副本，保留通用模板与其他国家模板；之后直接保存到该副本。切换模板／国家时保留各自尚未保存的草稿。邮件正文语言仍可自行编辑，不会自动翻译正文。

正文与链接区均支持 `{{partner_website}}`：台湾 `/tw`、日本 `/jp`、马来西亚 `/my`、泰国 `/th`、印度尼西亚 `/id`（导入「印尼」时自动合并）、菲律宾 `/ph`，其他国家（例如新加坡）默认 `/en`，域名为 `https://hiwin-partners.com`。已保存模板中的旧合作站地址已转换为此变量。预览按每个实际收件人的国家渲染并冻结链接；国家专用模板只允许该国家的正式收件人，同一批测试邮箱可使用模板绑定国家的网站检查效果。通用模板可跨国家并逐封使用对应网站。

## 记录分页

发送与回复记录默认每页 5 条，可选择每页 5／10／30／50／100 条，用上一页／下一页切换。记录区新增搜索框，可搜索机构、收件邮箱、主题、发件员工、发送／回复状态、下一步及附件名称，不区分英文大小写；多个关键词用空格分隔，须同时匹配。搜索与国家、发件员工和邮件类型筛选共同生效，分页及「选择当前筛选」均按搜索结果处理。改变搜索或筛选会清空记录勾选并回到第一页；改变每页数量也会回到第一页，不改变历史记录。

## 定时发送与预览

整批预览按邮件卡片展开；默认展开第一封，其他邮件点收件人标题核对。批准本批后自动收起整批正文，保留数量、摘要和发送操作，可随时展开查看。

发送方式默认为「立即发送」。选择「定时发送」才显示时间输入，按日本时间（Asia/Tokyo）安排；保存前确认时间、发件人、实际收件人和历史提醒。再次确认使用固定高度的弹窗，长名单在窗内滚动，确认与取消按钮始终可见。任务保存已批准的正文、附件、二维码及原发件账号，之后切换员工或编辑模板不改变任务。记录显示「测试发送／正式发送」、计划时间、实际发送时间、回复记录时间与状态。括号内显示收件人当地时间，印度尼西亚按雅加达（UTC+7）；测试邮箱未绑定国家时按日本时间，未知国家显示当地时间未设定。

关闭网页不影响定时任务。电脑须保持唤醒、工具程序运行，原发件账号须在当前运行中已连接；密码仍仅保存在内存。到时未连接时显示「待连接邮箱」，5 分钟内连接后继续执行；超过 5 分钟或工具重启时已错过时间，标为「已错过时间」且不补发，取消后可新建预览重新安排。新收到停止联系标记的任务显示「待重新确认」。发送失败或结果待核对不自动重试。待执行任务可在记录中「取消定时」，取消作用于整批邮件，已发出的邮件不受影响。有定时任务时记录区自动刷新状态，不修改正在编辑的模板。

## 删除发送记录

记录区每行提供「删除记录」，也可勾选多条、本页全选或选择当前筛选的全部可删除记录，再点击「删除已选」。确认后从本地列表移除，分页和筛选统计同步更新。切换筛选会清空勾选，翻页保留勾选。待执行的定时任务先取消后才能删除。已发出的邮件与 Google Sheet 日志保留。系统内部保留发送／回复凭据，后续二次确认仍显示发送历史，删除不清除停止标记。发送中的批次暂不能删除，执行结束后即可操作。

## Google Sheet 同步（首次配置）

现有 Codex 的 Google Drive 授权不能自动借给这个独立程序，需要单独接通。这里采用 Google 官方 Apps Script，仅用它把本地发送记录写入已有 Sheet。

1. 使用你的测试 Google 账号打开 <https://script.google.com>，创建项目，把 `SheetBridge.gs` 全部粘贴进编辑器并保存。
2. 本地工具刷新页面 → 展开 Google Sheet 同步设置 → 点击「生成并复制密钥」。项目设置 → 脚本属性，设置 `SPREADSHEET_ID` 为你的表格 ID，再设置 `BRIDGE_SECRET` 为刚复制的密钥并保存。本机 `local_config.json` 的 `spreadsheet_id` 须与脚本属性一致。保留本地工具页面，其中已自动填入同一密钥；不要把密钥发到聊天。
3. 部署 → 新部署 → Web 应用：执行身份选自己，访问选「任何人」。这是部署端点的访问范围；Google Sheet 本身保持原权限。代码仅接受带时间戳和签名的请求。Google 会要求你授权脚本写表，由你审核并完成授权。
4. 把 `/exec` 地址和同一个密钥填入本地页面「Google Sheet 同步设置」，点击「保存连接并验证」。地址与密钥保存在本机 Mac 钥匙串，启动自动读取；页面和数据库不返回或存储密钥。旧版仅存在内存，因此首次升级后需重新填入并保存一次。保存后密钥可留空；更换部署地址必须重新填写密钥。
5. 有新记录时自动同步到原表的「轻量工具日志」页；本地发送记录是恢复依据。不会覆盖「邮件跟踪」的原名单。同步失败时点击记录区出现的「重试 Sheet 同步」，不会重发邮件。

大量记录会按每次最多 40 条、实际请求不超过 250 KB 分批同步，保留完整正文。每批得到 Google 确认后才标为已同步；中途失败时保留已完成的批次，重试只处理尚未同步的记录。此更新沿用现有 Apps Script 部署地址与签名密钥，无须重新部署。

同步端点限制为固定表 ID 和固定日志页，用 Message-ID 更新同一条记录。需要撤销时在 Apps Script 管理部署中停用端点；不要把同步密钥写进源码。

## 收到回复后

点击记录区右上角「检查回复与退信」自动列出当前员工邮箱的收信文件夹，读取最近 30 天来信，包括 INBOX、已删除、归档、垃圾邮件及自建文件夹；跳过已发送、草稿和不能打开的目录。全部以只读方式打开，批量读取不标记已读，也不移动或删除邮件。其他邮箱不参与本次检查。

同公司其他人只要保留原邮件引用，也能根据 Message-ID 匹配；退信也会检查附带的原邮件头。人工回复会停止自动跟进，由你准备下一步回复。退信区分地址无效、邮箱满、服务器问题和原邮件转发后失败；只有确定地址无效时才自动加入旧地址停止列表，邮箱满／服务器问题需人工确认后重发，转发失败不直接判定原收件地址错误。自动回复及投递通知不算人工回复。

重复扫描或同封邮件移到另一文件夹不会重复更新。已核对的同类状态、备注和下一步，以及已有人工回复，保留原记录。页面显示实际读取的文件夹、更新数量、未完成检查及 Sheet 同步结果；部分文件夹失败仍保留成功识别的记录，可重新检查，Sheet 失败可只重试同步。回复时间是检测时间。不同邮箱且没有原邮件引用的来信需要在邮箱中人工识别；同邮箱无引用来信标为「待人工匹配」。本工具不猜测关联，不自动生成或发送后续邮件，也不做后台轮询。

## 删除模板

模板编辑区点击「删除当前模板」并确认。关联国家会恢复通用模板，附件文件和发送记录保留；已批准但尚未发送的旧预览失效。初始模板删除后重启不会恢复，至少保留一个模板。有未结束定时任务时请先取消任务。台湾英文版随正文使用 LINE，普通英文版使用 WhatsApp。

## 自己设置正文格式

选中正文中的文字，点击工具栏的「加粗」或「斜体」；再点一次取消。标题作用于当前行或选中的整行。Mac 可用 ⌘B／⌘I，Windows 可用 Ctrl+B／Ctrl+I。未选中文字时会插入可替换的示例文字。

也可直接输入有限的 Markdown：`**文字**` 加粗、`*文字*` 斜体、`# 标题`／`## 标题`／`### 标题` 为三级标题（井号后有空格）。编辑区显示标记，整批预览与实际 HTML 邮件显示格式；纯文字邮件去除格式标记。网页和邮件均转义原始 HTML，不支持粘贴 HTML 排版。格式随模板保存；修改格式后须重新预览与批准。
